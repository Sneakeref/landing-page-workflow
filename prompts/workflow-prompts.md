# 每一步给 AI 的提示词模板

把 `{{ }}` 里的内容换成你自己的。

## 1. 拆解标杆（在复刻之前）

```
我要给 {{你的产品}} 做落地页，目标用户是 {{谁}}，核心行动是 {{注册 / 预约 / 购买}}。
下面是我选的标杆页面：{{URL}}。我选它是因为 {{一句话理由}}。

请只做结构分析，不要复制任何文案和素材：
1. 列出从上到下的区块顺序，以及每个区块的作用
2. Hero 的信息结构（标题 / 副标题 / 主 CTA / 次 CTA / 辅助信息）
3. 社会证明、定价、FAQ 的排版方式
4. CTA 出现的位置和节奏
5. 哪些做法值得我借鉴，哪些不适合我的产品阶段
```

## 2. 复刻骨架（用 url-to-code 或 website-rebuild）

```
用 url-to-code 复刻 {{URL}} 的页面骨架，仅用于学习页面结构。
要求：
- 桌面端与 390×844 移动端都要检查
- 把所有文案、配色、Logo、图片路径集中放到一个 content 文件里
- 把品牌相关的图片、Logo 全部换成占位图，不要保留原站素材
- 产出可以本地直接运行的纯前端项目
```

> 注意：这类 Skill 只应用于你拥有或有权重建的网站；对他人网站的复刻仅用于学习结构，不要把对方的文案、图片、Logo、品牌名、客户与数据带进你的成品，也不要原样公开或上线。

## 3. 换成自己的品牌

```
下面是我的品牌资料：
- 产品名：{{}}   一句话定位：{{}}
- 目标用户与痛点：{{}}
- 三个核心卖点：{{}}
- 真实数据 / 客户 / 评价（只用这些，不要编造）：{{}}
- 品牌色：{{}}   语气：{{专业 / 轻松 / 克制}}

请把 content 文件里的所有内容替换成我的，并遵守：
- 没有真实数据的地方留空或用明确标注的占位，不要编造数字和评价
- 标题控制在 20 字内，副标题 40 字内
- 完成后全站搜索 {{标杆品牌名}}，确认没有残留
```

## 4. 验收

```
请检查这个落地页：
1. 390 宽手机端是否有横向滚动 / 文字溢出
2. 每一屏是否只有一个主要 CTA
3. 有没有残留的标杆品牌名、域名、图片
4. 标题、描述、OG 图是否齐全
5. 给出 Lighthouse 的性能与无障碍问题清单和修复建议
```
